# Manifests

`Assets.init({ manifest })`: declaring every bundle up front, inline or from a URL.

```ts
import { Assets } from "pixi.js";

await Assets.init({
  manifest: {
    bundles: [
      { name: "load-screen", assets: [{ alias: "logo", src: "logo.png" }] },
      {
        name: "game",
        assets: [
          { alias: ["hero", "player"], src: "hero@{1,2}x.{webp,png}" },
          { alias: "tile", src: "tile.png", data: { scaleMode: "nearest" } },
        ],
      },
    ],
  },
});

await Assets.loadBundle("load-screen");
Assets.backgroundLoadBundle("game");
```

- `Assets.init()` runs once and must come before any load; a second or late call is ignored, so put `manifest`, `basePath` and preferences in one call ([assets](../assets.md#init-order)). Calling `Assets.add` or `addBundle` before `init` also runs before format and resolution detection; call `init` first, then add ad-hoc assets.
- `manifest` may be an `AssetsManifest` object or a URL string (`manifest: "assets/manifest.json"`), which is loaded as JSON first, e.g. one generated by `@assetpack/core`.
- Each entry is an `UnresolvedAsset`: an `alias` may be an array (all names return the same asset), `src` takes format (`{webp,png}`) and resolution (`@{1,2}x`) patterns ([resolution](resolution.md)), and `data` is forwarded to the parser.
- List a fallback format in `src` (`hero.{webp,png}`, not `hero.webp`); a single format leaves browsers without it nothing to fall back to.
